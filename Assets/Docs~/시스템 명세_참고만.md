> Unity 6, Input System 패키지 기준. 규칙은 「게임 진행 규칙」, 구현 방법은 「구현 메모」를 따른다.

## 구조 원칙
- 매니저는 씬에 하나씩 두고, 서로의 참조는 인스펙터로 연결한다.
- 매니저 간 통신은 C# 이벤트로 한다. 표시와 연출(UI, 조명, 사운드)은 이벤트를 구독만 하고, 게임 상태를 바꾸지 않는다.
- 입력 장치에 직접 접근하는 곳은 InputReader 하나뿐이다.
- 모든 수치는 GameConfig 하나에 모은다.
- 설비는 공통 기반 클래스(Facility)를 상속한다. 설비 C를 나중에 추가해도 다른 시스템은 고치지 않는다.

## 고장 이벤트 한 번의 흐름
1. 진행도가 고장 이벤트의 발생 지점에 도달하면, FaultScheduler가 이벤트에 정해진 설비들에 동시에 고장을 요청한다.
2. 각 Facility가 새 목표를 만들고 고장 상태가 되어 FacilityManager에 알린다.
3. FacilityManager가 설비마다 고장 이벤트를 보낸다. 모두 정상이던 상태에서의 첫 고장이면 시스템 이상 시작 이벤트도 보낸다.
	- SystemTimer 카운트다운 시작, MainPanelDisplay 붉은 불, FeedbackManager 사이렌, GameManager 진행도 정지
4. 플레이어가 PlayerInteractor로 장치를 조작하면, 장치가 소속 설비에 알리고 설비가 목표 달성을 검사한다.
5. 달성하면 설비가 자동으로 정상이 된다. 마지막 고장이었다면 FacilityManager가 정상 복귀 이벤트를 보낸다.
	- SystemTimer 정지 · 초기화, 사이렌 정지, 진행도 재개
6. 시간 안에 못 고치면 SystemTimer가 만료 이벤트를 보내고, GameManager가 내구도를 깎는다. 타이머는 다시 시작한다.

## 1. 입력 · 플레이어
### InputReader
- 역할 : Input Actions 에셋(PlayerControls)을 읽어 다른 스크립트에 값과 이벤트로 전달한다.
- 액션 : Move(WASD), Look(마우스 이동량), Interact(좌클릭 누름 / 뗌)
- 모드 : 게임 중에는 Player 액션 맵과 커서 잠금. 게임이 끝나면 GameManager의 요청으로 UI 모드(커서 해제)로 바꾼다.

### PlayerMovement
- 역할 : WASD 이동. CharacterController 사용. 달리기, 점프 없음.
- 수치 : 이동 속도

### PlayerLook
- 역할 : 마우스로 시점 회전. 좌우는 몸, 상하는 카메라를 돌린다.

### PlayerInteractor
- 역할 : 카메라 중앙(조준선)에서 Raycast로 상호작용 거리 안의 IInteractable을 찾아 누름 / 드래그 / 뗌을 전달한다.
- 드래그 중 : 마우스 이동량을 잡은 장치로 넘기고, PlayerMovement를 잠그고, PlayerLook의 감도를 낮춘다.
- 잠금 요청 : ManualViewer가 열려 있는 동안에도 PlayerMovement와 PlayerLook을 잠근다.
- 수치 : 상호작용 거리
 
## 2. 조작 장치 (프리팹)
### IInteractable
- 조작 가능한 모든 오브젝트의 공통 인터페이스
- 누름, 드래그(마우스 이동량), 뗌. 조준 강조가 필요하면 조준 시작 / 끝을 추가한다.

### ButtonDevice
- 프리팹 : Button
- 역할 : 클릭하면 On / Off가 바뀌는 버튼. 상태에 따른 불빛과 클릭음.
- 알림 : 상태가 바뀌면 소속 설비에 알린다.
- 구성 : 버튼 메시, 콜라이더, 발광 머티리얼, AudioSource

### SliderDevice
- 프리팹 : Slider
- 역할 : 드래그로 움직이는 슬라이더. 값은 0 ~ 1 연속값, 슬라이더마다 무게감이 다르다.
- 목표 : 설비가 목표 위치와 허용 범위를 지정한다. 범위 안에 들어오는 순간 '철컥' 소리.
- 소리 : 움직이는 동안 끄는 소리 루프
- 알림 : 값이 바뀌면 소속 설비에 알린다.
- 구성 : 레일, 손잡이(콜라이더), 레일 시작 / 끝 지점, AudioSource(끄는 소리, 철컥)
- 범위 안에 들어와도 시각 표시는 하지 않는다. '철컥' 소리로만 알린다.

### ManualViewer
- 역할 : 후면 벽의 매뉴얼. 다가가서 그대로 읽을 수 있고, 클릭하면 매뉴얼 UI(화면 공간)를 확대해서 띄운다.
- 열기 / 닫기 : 누를 때마다 토글한다. 열려 있는 동안 시점이 잠겨 조준선이 매뉴얼에 그대로 있으므로, 다시 클릭하면 닫힌다.
- 잠금 : 열 때 PlayerInteractor에 잠금을 요청하고, 닫을 때 해제한다. 게임(진행도, 타이머)은 멈추지 않는다.
- 구성 : 벽의 매뉴얼 메시와 월드 공간 텍스트, 콜라이더, 확대 UI 패널

## 3. 설비
### Facility
- 기반 클래스. 모든 설비의 공통 동작.
- 상태 : 정상 / 고장. 고장 플래그(`isFault`)로만 판단한다. 장치 상태로 계산하지 않는다.
- ID : A / B / C. 고장 이벤트가 대상 설비를 지정할 때 쓴다.
- 고장 : 고장 요청을 받으면 현재 장치 상태와 겹치지 않는 새 목표를 만들고 고장 상태가 된다. 장치는 현재 상태를 유지한다.
- 수리 : 고장 상태에서 장치가 바뀔 때마다 목표 달성을 검사하고, 달성하면 정상이 되고 장치를 초기화한다. 정상 상태에서는 검사하지 않는다 (장치만 반응).
- 알림 : 수리 완료 때만 FacilityManager에 알린다. 장치 초기화는 설비가 스스로 한다.
- 하위 클래스가 채울 것 : 목표 생성, 목표 달성 검사, 장치 초기화 (「설비 고장 플래그 · 수리 후 초기화 계획」 3장)

### FacilityA
- 4x4 버튼 설비. 좌측면. ButtonDevice 16개를 가진다.
- 목표 : N칸 On 형태, 현재 형태와 M칸 이상 다르게
- 목표 표시 : TargetPatternDisplay

### TargetPatternDisplay
- A의 목표 형태를 4x4 격자로 보여주는 화면. 고장일 때만 표시한다.
- 위치 : 좌측면, A 버튼 바로 위

### FacilityB
- 슬라이더 설비. 우측면. SliderDevice 4개를 가진다.
- 목표 : 슬라이더마다 현재 위치에서 허용 범위 밖에 목표 위치 생성
- 달성 : 4개 모두 범위 안
- 목표 위치와 범위 안 여부는 화면에 보여주지 않는다. 소리로만 찾는다.

### FacilityC
- [미정] A, B를 완성한 뒤 시간이 남으면 추가한다.

## 4. 코어 매니저 · 데이터
### FacilityManager
- 역할 : 모든 설비를 등록해 두고 시스템 전체 상태를 모은다.
- 제공 : ID로 설비 찾기, 정상 설비 목록, 현재 고장 수, 모두 정상인지
- 이벤트 : 설비 고장, 설비 수리, 시스템 이상 시작(정상 → 첫 고장), 시스템 정상 복귀(마지막 수리)

### FaultScheduler
- 역할 : 진행도에 걸어 둔 고장 이벤트를 발생시킨다.
- 준비 : 게임 시작 시 GameConfig의 고장 이벤트마다 발생 구간 안에서 발생 지점을 무작위로 정한다.
- 규칙 : GameManager의 진행도 변경을 구독한다. 진행도가 다음 이벤트의 발생 지점에 도달하면, 이벤트의 설비들에 동시에 고장을 요청한다.
	- 설비 ID가 지정된 이벤트는 FacilityManager에서 ID로 찾고, '무작위 N개' 이벤트는 정상 설비 중 무작위로 고른다.
- 고장 중에는 진행도가 멈추므로 이벤트가 겹치지 않는다. 난이도는 이벤트 표의 동시 고장 수로 조절한다.
- 게임이 끝나면 멈춘다.

### SystemTimer
- 역할 : 시스템 이상 타이머. 시스템 전체가 정상이 아닌 시간을 잰다.
- 동작 : 시스템 이상 시작 → 카운트다운 / 일부 수리 → 영향 없음 / 0 도달 → 만료 이벤트 후 재시작 / 시스템 정상 복귀 → 정지, 초기화
- 동시 고장은 한 순간에 함께 발생하고 타이머가 도는 동안 고장이 추가되지 않으므로, 추가 고장 처리는 두지 않는다.
- 이벤트 : 시작, 남은 시간 변경, 만료, 정지
- 게임이 끝나면 멈춘다.

### GameManager
- 역할 : 게임 흐름, 진행도, 내구도를 관리한다.
- 상태 : 진행 중 / 승리 / 패배, 진행도(0 ~ 100%), 내구도
- 진행도 : 시스템이 모두 정상일 때만 증가한다.
- 내구도 : SystemTimer가 만료되면 감소한다. 낮음 기준 아래로 내려가면 '내구도 낮음' 이벤트를 보낸다.
- 종료 : 진행도 100% → 승리, 내구도 0 → 패배. FaultScheduler와 SystemTimer를 멈추고 InputReader를 UI 모드로 바꾼다.
- 재시작 : 씬을 다시 불러온다.
- 이벤트 : 진행도 변경, 내구도 변경, 내구도 낮음, 승리, 패배

### GameConfig
- ScriptableObject. 「게임 진행 규칙」 10. 수치의 모든 값과 4. 고장 이벤트 표를 담는다.
- 고장 이벤트 : 발생 구간(최소 ~ 최대 %), 고장 설비 ID 목록 또는 무작위 고장 수
- 매니저, 설비, 플레이어가 읽기만 한다.

## 5. 표시 · 연출
### MainPanelDisplay
- 전면 메인 패널 (월드 공간 UI)
- 설비별 표시등(FacilityManager), 디지털 타이머(SystemTimer), 진행도 바와 내구도 게이지(GameManager)
- 고장 수가 늘면 붉은 표시 면적을 넓힌다.

### FeedbackManager
- 역할 : 공간 조명과 전역 사운드
- 평상시 : 초록 조명, 기계 소리 / 고장 : 붉은 조명, 사이렌(고장 수만큼 음량 증가) / 수리 성공 : 성공음 / 정상 복귀 : 사이렌 정지 / 만료 : 경고음 / 내구도 낮음 : 앰비언스 추가 / 승리, 패배 : 결과음
- 장치 개별 소리(클릭, 끄는 소리, 철컥)는 각 장치 프리팹이 낸다.

### ResultUI
- 승리 / 패배 화면 (화면 공간 UI). 재시작 버튼은 GameManager의 재시작을 부른다.

### HUD
- 화면 중앙 조준점

## 6. 폴더 · 씬 구성
### 폴더
```
Assets/_Project/
├─ Scripts/  Input, Player, Interaction, Facilities, Core, Presentation
├─ Prefabs/  Devices(Button, Slider), Facilities(FacilityA, FacilityB), UI
├─ Input/    PlayerControls.inputactions
├─ Data/     GameConfig.asset
├─ Audio/ · Materials/
└─ Scenes/   Main.unity
```

### 씬 (Main)
- Managers : GameManager, FacilityManager, FaultScheduler, SystemTimer, FeedbackManager
- Player : InputReader, PlayerMovement, PlayerLook, PlayerInteractor, Camera
- Room : 벽, 조명, ManualViewer(후면), MainPanelDisplay(전면), FacilityA와 TargetPatternDisplay(좌측면), FacilityB(우측면) (배치는 「게임 진행 규칙」 2. 설비 배치)
- UI : HUD, ResultUI, 매뉴얼 확대 UI
