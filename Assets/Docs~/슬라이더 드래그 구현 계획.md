> **변경됨** : 드래그 중 "시점 · 이동 정지"는 「슬라이더 드래그 중 시점 감도 계획」으로 바뀌었다 (이동만 정지, 시점은 낮은 감도로 회전, 레일 축은 매 프레임 재계산). 이 문서의 1장 요구 사항, 4장 StartDrag / StopDrag, 6장 계산 설명, 8장 흐름, 9장 D5, 11장 #2 중 잠금 · 고정 카메라 전제 부분은 그 문서를 따른다

> **목적** : 설비 B의 슬라이더 장치를 만든다. 플레이어가 조준선으로 **슬라이더 손잡이를 잡고, 누른 채 드래그해서** 레일을 따라 움직일 수 있게 한다.
> **규칙** : 「게임 진행 규칙」 7장 설비 B, 10장 수치. (「게임 진행 규칙」이 참조하는 「구현 메모」의 슬라이더 드래그 항목은 이 문서로 대신한다.)

## 1. 배경

### 요구 사항 (「게임 진행 규칙」 7장)
- 슬라이더 손잡이를 클릭한 채 드래그한다. 값은 연속값이다.
- 슬라이더마다 무게감이 다르다. 같은 양을 드래그해도 무거울수록 적게 움직인다 (1.0 / 0.7 / 0.5 / 0.3).
- 슬라이더를 잡고 있는 동안 시점 회전과 이동을 멈춘다.
- 잡고 움직이는 동안 끄는 소리, 목표 범위에 들어가는 순간 '철컥' 소리. 범위 안 여부는 시각적으로 표시하지 않는다.

### 현재 코드와의 차이

| 항목 | 현재 | 필요한 것 |
| --- | --- | --- |
| `FirstPersonController.OnClick` | `performed`(누름) 순간 한 번 Raycast → `IInteractable.Interact()` | **뗌(release)** 처리 |
| 드래그 입력 | 없음 | 잡는 동안 마우스 이동량을 슬라이더로 전달 |
| `SetInputLocked(bool)` | 카운트 방식으로 있음. 호출자 없음 | 그대로 사용한다 (재작성 계획 6장에서 슬라이더용으로 만들어 둔 자리) |
| `FirstPersonCamera` | 시점 잠금 중에는 Look 입력을 버린다 | 수정하지 않는다. 드래그용 이동량은 컨트롤러가 따로 받는다 (4장) |
| `IInteractable` | `Interact()` 하나 | 드래그용 인터페이스 추가 (3장) |
| `FacilitySlider` | 빈 `Interact()`만 있음 | 장치 구현 (6장) |
| `Click` 액션 | Button 타입, interaction 없음 | 누르면 `performed`, 떼면 `canceled`가 온다. **입력 에셋 수정 없음** |
| 레이어 | `Slider` 레이어(7번) 있음 | `interactLayerMask`에 추가 |

## 3. 인터페이스 : IDraggable

```csharp
public interface IDraggable
{
    void BeginDrag(Camera cam);      // 잡는 순간 한 번
    void Drag(Vector2 mouseDelta);   // 잡고 있는 동안 매 프레임 (픽셀 단위 마우스 이동량)
    void EndDrag();                  // 놓는 순간 한 번
}
```

- `IInteractable`에 누름 / 드래그 / 뗌을 넣지 않고 **별도 인터페이스로 둔다** (D1). `FacilityButton`이 빈 메서드 세 개를 구현할 필요가 없고, 버튼 코드를 건드리지 않는다.
- 컨트롤러는 맞은 대상에서 **`IDraggable`을 먼저** 찾고, 없으면 `IInteractable`을 찾는다.
- `FacilitySlider`는 `IInteractable` 대신 `IDraggable`을 구현한다.
- 파일 위치 : `Assets/Scripts/Facility/IDraggable.cs` (`IInteractable.cs` 옆)

## 4. FirstPersonController 변경

### 추가 내부 상태

| 상태 | 설명 |
| --- | --- |
| `_dragTarget : IDraggable` | 지금 잡고 있는 대상. null이면 드래그 중이 아니다 |
| `_dragDelta : Vector2` | 이번 프레임까지 누적된 마우스 이동량 |

### 추가 · 변경 공개 API

| 멤버 | 설명 |
| --- | --- |
| `OnClick(InputAction.CallbackContext)` | `performed`(누름)와 `canceled`(뗌)를 모두 처리한다 |
| `OnLook(InputAction.CallbackContext)` | **새로 추가.** 드래그 중일 때만 `_dragDelta`에 누적한다 (`performed`만, 대입이 아니라 더하기) |
| `bool IsDragging` | `_dragTarget != null` |

### 동작

**좌클릭 (OnClick)**

```
OnClick
├─ canceled (뗌)
│   └─ 드래그 중이면 StopDrag()                     ← 반드시 잠금 검사보다 먼저
└─ performed (누름)
    ├─ 커서가 풀려 있음  → 다시 잠그고 끝 (기존과 같음)
    ├─ 입력 잠금 중      → 무시
    └─ TryInteract()
```

- **뗌 처리를 `IsInputLocked` 검사보다 먼저 한다.** 드래그 중에는 컨트롤러 스스로 잠금을 걸어 두므로, 순서가 바뀌면 영원히 놓을 수 없다.
- 커서 재잠금 클릭의 뗌은 `_dragTarget`이 없으므로 아무 일도 일어나지 않는다.

**TryInteract (변경)**
1. Raycast는 기존과 같다 (카메라 중앙, `interactDistance`, `interactLayerMask`, 트리거 무시).
2. `hit.collider.GetComponentInParent<IDraggable>()`가 있으면 → `StartDrag(draggable)`
3. 없으면 `GetComponentInParent<IInteractable>()` → `Interact()` (기존과 같음)

**StartDrag / StopDrag**

```
StartDrag(target)
├─ _dragTarget = target, _dragDelta = 0
├─ SetInputLocked(true)                  ← 이동 · 시점 · 새 상호작용 정지
└─ target.BeginDrag(firstPersonCamera.Camera)

StopDrag()
├─ _dragTarget이 null이면 바로 반환      ← 여러 경로에서 불려도 안전해야 한다
├─ target.EndDrag()
├─ _dragTarget = null, _dragDelta = 0
└─ SetInputLocked(false)                 ← 잠금 카운트를 정확히 한 번만 줄인다
```

**드래그 전달 (Update)**
1. 드래그 중이 아니면 `_dragDelta`를 비우고 끝.
2. 커서가 풀려 있으면(드래그 중 Esc) `StopDrag()` 후 끝.
3. `_dragTarget.Drag(_dragDelta)`, `_dragDelta = 0`.
- 이동량에 `Time.deltaTime`을 곱하지 않는다 (마우스 delta는 이미 프레임 이동량이다).
- 카메라 감도(`sensitivity`)도 곱하지 않는다. 픽셀 이동량 그대로 넘긴다 (5장 계산이 픽셀 기준이다).

**강제 종료 경로** : 전부 `StopDrag()` 하나로 모은다.

| 상황 | 처리 위치 | 이유 |
| --- | --- | --- |
| 드래그 중 Esc (커서 해제) | `Update`에서 `!IsCursorLocked` 검사 | 컨트롤러는 Escape 입력을 받지 않는다. 커서 상태로 판단한다 |
| 창 포커스 상실 (Alt+Tab) | `OnApplicationFocus(false)` | 창 밖에서 버튼을 떼면 `canceled`가 오지 않을 수 있다 |
| 컴포넌트 비활성화 | `OnDisable` | 잠금 카운트가 남지 않게 한다 |
| 게임 종료 (UI 모드 전환) | 후속 작업에서 같은 함수 호출 | |

**기타**
- 잡은 뒤에는 거리를 다시 검사하지 않는다. 이동과 시점이 모두 잠겨 있으므로 필요 없다.
- `Reset()`의 기본 마스크를 `LayerMask.GetMask("Button", "Slider")`로 바꾼다. 이미 씬에 붙어 있는 컴포넌트는 인스펙터에서 Slider를 추가로 체크한다.

### 마우스 이동량을 받는 방법 (D2)

| 방안 | 내용 | 판단 |
| --- | --- | --- |
| **A. PlayerInput `Look` 이벤트에 리스너 추가** | `Look` 이벤트에 `FirstPersonCamera.OnLook`과 `FirstPersonController.OnLook`을 함께 연결한다 (Unity Events는 리스너를 여러 개 받는다) | **채택.** 카메라 수정 없음, 참조 방향(플레이어 → 카메라) 유지 |
| B. 카메라가 버린 delta를 공개 | 잠금 중 `_lookInput`을 카메라가 넘겨준다 | 카메라가 드래그를 알아야 한다. 책임이 섞인다 |
| C. `Mouse.current.delta` 직접 읽기 | 컨트롤러에서 바로 읽는다 | 입력 장치 직접 접근은 한 곳만이라는 원칙(「시스템 명세」)에 어긋난다 |

## 6. FacilitySlider (장치) 명세

### 프리팹 구성

```
Slider                  ← FacilitySlider, AudioSource(끄는 소리 루프), AudioSource(철컥)
├ Rail                  ← 메시만. Slider 레이어가 아니다
├ RailStart             ← 빈 Transform. 값 0 위치
├ RailEnd               ← 빈 Transform. 값 1 위치
└ Handle                ← 메시 + BoxCollider. Slider 레이어
```

- **Slider 레이어는 손잡이에만 둔다.** 레일이나 빈 곳을 클릭하면 Raycast에 걸리지 않으므로 "손잡이를 잡는다"는 조건이 구조로 지켜진다.
- 컨트롤러가 `GetComponentInParent`를 쓰므로 Handle 콜라이더가 맞아도 루트의 `FacilitySlider`를 찾는다.
- 2m 거리에서는 손잡이가 작게 보인다. 콜라이더를 메시보다 조금 크게 잡는다.
- 레일의 위 / 아래 방향은 RailStart / RailEnd 배치로 정한다. 코드는 방향을 가정하지 않는다.

### 인스펙터 필드 (안)

| 필드 | 타입 | 기본값 | 설명 |
| --- | --- | --- | --- |
| `handle` | Transform | — | 움직일 손잡이 |
| `railStart` / `railEnd` | Transform | — | 값 0 / 1 위치 |
| `weight` | float | 1 | 무게감. 드래그 양 대비 움직이는 비율. 「게임 진행 규칙」 10장 : 1.0 / 0.7 / 0.5 / 0.3 |
| `initialValue` | float | 0 | 시작 값 (0 ~ 1) |
| `minScreenAxisLength` | float | 50 | 픽셀. 레일을 거의 끝에서 바라볼 때의 보정 (아래 계산 참고) |
| `dragLoopSource` | AudioSource | — | 끄는 소리 루프 |
| `snapSource` | AudioSource | — | 범위 진입 '철컥' |
| `dragSoundHoldTime` | float | 0.1 | 초. 값이 이 시간 동안 변하지 않으면 끄는 소리를 멈춘다 |

### 내부 상태

| 상태 | 설명 |
| --- | --- |
| `_value : float` | 현재 값 (0 ~ 1) |
| `_screenAxis : Vector2` | 잡는 순간 계산한, 값 0 → 1이 화면에서 차지하는 픽셀 벡터 |
| `_target : float`, `_tolerance : float`, `_hasTarget : bool` | 설비가 지정한 목표 위치와 허용 범위 |
| `_isInRange : bool` | 직전 프레임에 범위 안이었는지. 밖 → 안 전환 감지용 |
| `_lastMoveTime : float` | 마지막으로 값이 바뀐 시각. 끄는 소리 정지 판단용 |

### 공개 API (안)

| 멤버 | 설명 |
| --- | --- |
| `float Value` | 현재 값 |
| `bool IsInRange` | 목표가 있고 `|value - target| <= tolerance / 2` |
| `event Action OnValueChanged` | 값이 바뀌면 소속 설비에 알린다 |
| `void Initialize()` | 값을 `initialValue`로, 손잡이 위치 갱신. 설비가 부른다 (FacilityButton과 같은 패턴) |
| `void SetTarget(float target, float tolerance)` | 목표 지정. `_isInRange`를 현재 값으로 다시 계산한다 (지정 직후 '철컥'이 나지 않게) |
| `void ClearTarget()` | 목표 해제. 정상 상태에서는 범위 소리를 내지 않는다 |
| `BeginDrag` / `Drag` / `EndDrag` | `IDraggable` 구현 |

### 핵심 : 레일 방향으로 움직이는 계산 (D3)

**화면 공간 투영 방식**을 쓴다.

```
BeginDrag(cam)
  a = cam.WorldToScreenPoint(railStart.position)
  b = cam.WorldToScreenPoint(railEnd.position)
  _screenAxis = (Vector2)(b - a)
  길이가 minScreenAxisLength보다 짧으면 방향은 유지하고 길이만 늘린다 (방향도 0이면 화면 위쪽)

Drag(delta)
  _value += Vector2.Dot(delta, _screenAxis) / _screenAxis.sqrMagnitude * weight
  _value  = Mathf.Clamp01(_value)
  handle.position = Vector3.Lerp(railStart.position, railEnd.position, _value)
  값이 바뀌었으면 → OnValueChanged, 끄는 소리, 범위 진입 검사
```

- **weight 1.0이면 손잡이가 마우스를 화면상 픽셀 단위로 정확히 따라온다.** 잡고 끄는 느낌을 주는 핵심이다. weight 0.3이면 같은 양을 끌어도 30%만 움직인다.
- 슬라이더가 세로든 가로든, 비스듬히 보든 방향이 자동으로 맞는다. 위로 끌면 화면상 위쪽 끝으로 간다.
- 드래그 중에는 카메라가 고정되므로 잡는 순간 한 번 계산한 `_screenAxis`를 끝까지 쓴다.
- 레일과 수직인 방향의 마우스 이동은 내적에서 사라진다. 비스듬히 끌어도 레일 방향 성분만 반영된다.
- 대안 : `delta.y * 상수`만 쓰는 방식은 더 단순하지만, 정면을 향한 세로 슬라이더에서만 맞는다.

### 소리

| 상황 | 처리 |
| --- | --- |
| 값이 바뀜 | `dragLoopSource`가 멈춰 있으면 재생. `_lastMoveTime` 갱신 |
| `dragSoundHoldTime` 동안 값 변화 없음 | `Update`에서 `dragLoopSource` 정지 (잡고 멈춰 있을 때 소리가 계속 나지 않게) |
| `EndDrag` | `dragLoopSource` 정지 |
| 범위 밖 → 안 전환 | `snapSource.PlayOneShot` 한 번. 안 → 밖은 소리 없음 |
| 레일 끝에 닿아 값이 더 변하지 않음 | 값 변화가 없으므로 끄는 소리가 자연스럽게 멈춘다 |

- 범위 진입 소리는 **목표가 있을 때만**(설비 고장 중) 낸다. 정상 설비의 조작은 아무 일도 일어나지 않는다는 규칙(「게임 진행 규칙」 6장)을 따른다.
- 시각 표시는 하지 않는다.

## 7. FacilityB (설비) 책임 정리 (후속 작업)

> **변경됨** : 고장 판정 · 수리 · 초기화 구조는 「설비 고장 플래그 · 수리 후 초기화 계획」을 따른다 (고장 플래그, 수리 시 슬라이더 기본값으로 초기화, 알림은 수리 때만).

이번 범위 밖이지만, 장치 API가 이것을 받칠 수 있어야 하므로 책임만 적어 둔다.

| 항목 | 내용 |
| --- | --- |
| 구성 | `FacilitySlider` 4개 (인스펙터 배열), 각자 weight 1.0 / 0.7 / 0.5 / 0.3 |
| `Initialize` | 슬라이더 `Initialize()`, `OnValueChanged` 구독 |
| `MakeFault` | 슬라이더마다 현재 값에서 허용 범위 밖에 목표를 무작위 생성 → `SetTarget(target, 0.1f)` |
| `IsFault` | 하나라도 `!IsInRange`면 true |
| 수리 | `OnValueChanged` 때 `OnFacilityInteracted?.Invoke(IsFault(), facilityID)` (FacilityA와 같은 패턴). 수리되면 `ClearTarget()` |
| `Clear` | 목표 해제 |

- 목표를 한 번도 지정하지 않은 초기 상태에서 `IsFault`가 false가 되도록 한다 (FacilityA가 정상으로 시작하는 것과 맞춘다).
- 설비 B를 FacilityManager에 등록하면 MainPanelDisplay 슬롯도 늘려야 한다 (「코드 구조 분석」 12장 문제 15).

## 8. 조작 흐름 (완성 후)

```
조준선이 손잡이(Slider 레이어, 2m 이내)에 있음
     │ 좌클릭 누름
     ▼
FirstPersonController.TryInteract → IDraggable 발견
     ├ SetInputLocked(true)           → 이동 · 시점 정지
     └ FacilitySlider.BeginDrag(cam)  → 화면상 레일 축 계산
     │ 누른 채 마우스 이동
     ▼
PlayerInput Look ─┬→ FirstPersonCamera.OnLook      (잠금 중이라 버림)
                  └→ FirstPersonController.OnLook  (_dragDelta 누적)
Update → FacilitySlider.Drag(delta) → 손잡이 이동, 끄는 소리, 범위 진입 시 '철컥'
                                    → OnValueChanged → (FacilityB 목표 검사)
     │ 좌클릭 뗌 (또는 Esc / 포커스 상실 / 비활성화)
     ▼
StopDrag → EndDrag(끄는 소리 정지) → SetInputLocked(false) → 이동 · 시점 복귀
```

## 9. 결정 사항 (기본안)

| # | 항목 | 기본안 |
| --- | --- | --- |
| D1 | 드래그 인터페이스 | `IInteractable` 확장이 아니라 **별도 `IDraggable`**. 버튼 코드는 수정하지 않는다 |
| D2 | 드래그 이동량 수신 | **PlayerInput `Look` 이벤트에 `FirstPersonController.OnLook` 리스너 추가** (4장 방안 A) |
| D3 | 이동 계산 | **화면 공간 투영, weight 1.0 = 마우스와 1:1.** 고정 감도 상수는 두지 않는다 |
| D4 | 잡을 수 있는 부위 | **손잡이만** (Slider 레이어는 Handle에만). 레일을 클릭해 점프 이동하는 기능은 없다 |
| D5 | 잡은 뒤 거리 검사 | **하지 않는다.** 이동 · 시점이 잠겨 있으므로 놓을 때까지 유지 |
| D6 | 손잡이 조준 하이라이트 | **이번 범위에서 제외.** 버튼 하이라이트 방식(재작성 계획 7장)이 정해지면 같은 방식을 따른다 |

## 10. 작업 순서

1. `IDraggable` 추가
2. `FirstPersonCamera`에 `Camera` 접근자 추가
3. `FirstPersonController` 수정 : `OnClick` 누름 / 뗌 분리, `OnLook`, `StartDrag` / `StopDrag`, `Update` 드래그 전달, 강제 종료 경로, 기본 마스크에 Slider 추가
4. `FacilitySlider` : 손잡이 이동과 무게감만 먼저 구현
5. 테스트 씬에 Slider 프리팹 하나 배치, PlayerInput `Look`에 리스너 추가, 인스펙터 마스크에 Slider 체크 → 드래그 확인
6. `FacilitySlider` : 끄는 소리, 목표 지정과 범위 진입 소리 추가 (목표는 임시로 인스펙터나 테스트 코드에서 지정)
7. weight가 다른 슬라이더 4개를 배치해 무게감 확인
8. 11장 완료 기준 확인
9. (후속) `FacilityB` 작성 후 FacilityManager 등록

## 11. 완료 기준

| # | 확인 항목 |
| --- | --- |
| 1 | 조준선이 2m 안의 손잡이에 있을 때 좌클릭을 누른 채 마우스를 움직이면 손잡이가 레일을 따라 움직인다 |
| 2 | 드래그 중에는 WASD와 마우스 시점이 동작하지 않는다. 놓으면 바로 복귀한다 |
| 3 | weight 1.0 슬라이더는 손잡이가 화면에서 마우스 이동량만큼 따라오고, 0.3 슬라이더는 눈에 띄게 적게 움직인다 |
| 4 | 세로 / 가로 / 비스듬히 배치한 슬라이더 모두 끄는 방향으로 움직인다. 레일 끝에서 멈추고 넘어가지 않는다 |
| 5 | 레일, 벽, 빈 공간, 2m보다 먼 손잡이를 클릭하면 아무 일도 없고 오류도 없다 |
| 6 | 드래그 중 Esc, Alt+Tab 후에도 이동 · 시점 잠금이 남지 않는다 (`IsInputLocked == false`) |
| 7 | 끄는 소리는 움직이는 동안만 나고, 잡은 채 멈추거나 놓으면 멈춘다 |
| 8 | 목표가 지정된 상태에서 범위에 들어가는 순간 '철컥'이 한 번 난다. 범위 안에서 움직여도 반복되지 않는다. 목표가 없으면 나지 않는다 |
| 9 | 버튼(`FacilityButton`) 클릭은 기존대로 동작한다 |
